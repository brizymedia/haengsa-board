# 블로그 체계 — `_blog` 원본 → 생성기 → `/blog/`

HD기획 사이트의 블로그는 2026-10-13 에 큰길이벤트기획 `_blog` 루틴을 옮겨 왔고(README),
이후 다른 고객 사이트들이 **이 HD기획판**을 원조로 다시 옮겨 갔다. HD기획판에서 바뀐 점(파일 머리 주석 기준):
- 사진은 CDN 이 아니라 **이 저장소 `/assets/img/`** 를 쓴다(build-blog.mjs).
- 네이버 원고 검사는 뺐다(blog-check.mjs).
- 2026-10-28: llms.txt 「## 블로그」 절이 다시 돌릴 때마다 겹치던 버그 수정(아래 4-4).

목표(GUIDE): 네이버 웹문서 · 구글 · AI 검색에서 「지역 + 행사 준비」 검색에 걸리는, 담당자가 저장해 두고 싶은 체크리스트.
원칙: **틀린 정보 한 줄이 글 한 편보다 해롭다. 확인 못 한 것은 쓰지 않는다.**

## 1. 구성 파일

```
_blog/
  GUIDE.md            규칙(사람이 고칠 때도 이것부터)
  posts/<YYYY-MM-DD>-<slug>.json   글 원본
  regions.json        지역 자료(비중 · 이동 · 동네 · 많은행사 · 주의 · 현장기록)
  keywords.json       주제 틀 · 지역전용 · 검색량 · 보정
  photos.json         쓸 수 있는 사진 묶음 + 제외 사유
  sources.json        사람이 확인한 공식 출처 + 「사실」 범위
  indexnow-key.txt    IndexNow 키
scripts/
  build-blog.mjs      생성기 (export: SITE BRAND esc 인라인 글자만 날짜글 글주소 지역표 사진목록 글읽기 본문글 글이미지들 buildBlog)
  blog-check.mjs      검사기 (build-blog.mjs 의 함수를 import)
  blog-plan.mjs       계획기 (글읽기 를 import)
```
의존성 없음. Node 의 `node:fs` · `node:path` · `node:url` 만 쓴다(ESM `.mjs`). 이 분석 환경 Node v22 에서 세 스크립트 모두 돌았다.

## 2. 하루 작업 순서 (GUIDE 1장)

```bash
node scripts/blog-plan.mjs                 # 1) 오늘 쓸 글 5개(지역 · 주제 · 핵심/보조 키워드)
#    2) 글마다: regions.json 의 그 지역 이동 · 동네 · 많은행사 · 주의 · 현장기록을 읽고,
#       같은 주제 다른 지역 글은 읽되 베끼지 않고, 법 · 기준은 sources.json 범위 안에서만,
#       photos.json 에서 사진 3~4장 → _blog/posts/<날짜>-<slug>.json 작성(근거 칸 필수)
node scripts/blog-check.mjs --new _blog/posts/2026-10-28-광명-송년회-….json   # 3) 통과할 때까지
node scripts/build-blog.mjs                # 4) blog/ · rss.xml · sitemap.xml · llms.txt 갱신
git add -A && git commit -m "블로그: …" && git push   # 5) Pages 반영(1분 안팎)
#    6) IndexNow · 네이버 서치어드바이저 알림은 사람이(또는 스크립트로)
```
검사기를 통과시키려고 동네 이름이나 자료 문장을 억지로 끼워 넣지 않는다 — 그럴 거면 그 글을 버린다(GUIDE).

**루틴**: `blog-plan.mjs --json` 은 「루틴이 읽는 JSON」, sources.json 설명에 「루틴 환경에서는 정부 누리집을 WebFetch 로 열 수 없어서」라는 말이 있다.
즉 예약 실행되는 Claude 루틴이 위 순서를 도는 것을 전제로 만들었다. **루틴 설정(프롬프트 · 주기)은 이 레포에 없다 — 확인 필요.**

## 3. 글 JSON 형식 (GUIDE 3장 + 검사기 기준)

| 칸 | 규칙 |
|---|---|
| `slug` | `^[가-힣a-z0-9]+(-[가-힣a-z0-9]+)*$`, 70자 이하, 지역 slug · `page` 금지, 중복 금지 |
| `date` | `YYYY-MM-DD`, 한국 날짜로 오늘 이후 금지. 파일 이름 = `<date>-<slug>.json` |
| `region` | regions.json slug 또는 `common` |
| `topic` | keywords.json topic. 같은 지역 · 같은 topic 은 한 번만 |
| `title` | 15~50자, 지역 이름 + 핵심 키워드 통째로 |
| `description` | 70~160자, 핵심 키워드(또는 lead 에) |
| `keyword` | `{ "main": "…", "sub": ["…"] }` |
| `lead` | 80~420자, 첫 문장에 핵심 키워드와 결론 |
| `points` | 3~5개(AI 검색이 인용하는 자리) |
| `cover` | `{ path, alt, caption }` — path 는 `/assets/img/…` |
| `sections` | 4개 이상(GUIDE 는 4~8), `{ h2: "1. …", blocks: [...] }` |
| `faq` | 2~6개 `{ q, a }` |
| `근거` | 3개 이상 `{ 내용, 출처 }` — 내용은 본문에 **그대로** 있는 구절, 출처는 `"regions.json"` 또는 이 글 sources 의 url. regions.json 근거는 25자 이하, 그중 하나 이상은 `이동 · 주의 · 현장기록` 에서 (`common` 글은 근거 검사 없음) |
| `sources` | `[{ name, url }]` (없으면 `[]`). https 만. 공식 기관 도메인이면 sources.json 주소 그대로 |
| `updated` | (선택) dateModified · sitemap lastmod 에 쓰임 |

blocks: `{p}` · `{ul:[]}` · `{ol:[]}` · `{table:{head:[],rows:[[]]}}`(칸 수 = 머리 수) · `{img:{path,alt,caption}}` · `{tip}`(「현장 메모」 상자).
인라인 꾸밈은 `**굵게**` 와 `[글자](/주소 또는 https://…)` 뿐(`인라인()`).

## 4. 생성기 `build-blog.mjs` 가 하는 일

1. `_blog/posts/*.json` 을 읽어 date 내림차순(같으면 slug 오름차순).
2. `blog/` 를 **통째로 지우고**(`rmSync`) 다시 만든다:
   - 글 `/blog/<encodeURIComponent(slug)>/index.html`
   - 목록 `/blog/` (24개씩, 넘으면 `/blog/page/N/`)
   - 지역 모음 `/blog/<region>/` — regions.json 의 모든 지역 + 글이 있을 때만 `common`. 글 없는 지역은 `noindex,follow`.
3. **sitemap.xml**: 기존 파일에서 `/blog/` 가 든 `<url>` 줄만 지우고 `</urlset>` 앞에 새로 넣는다(파일이 없으면 건드리지 않음).
4. **llms.txt**: 「## 블로그」로 시작하는 절부터 다음 「## 」 절 앞(없으면 끝)까지를 새 목록으로 바꾼다. 절이 없으면 끝에 붙인다. 글이 0개면 건드리지 않는다.
   (옛 방식은 `m` 플래그의 `$` 가 줄 끝에 걸려 두 번째 실행부터 목록이 겹쳤다 — 이식할 때 옛 판을 가져오지 말 것)
5. **rss.xml**: 최근 50편, pubDate = 날짜 09:00 KST.
6. 공통: canonical · og · twitter 카드 · RSS alternate · stats.js(`data-site="hd"`) · JSON-LD(BreadcrumbList · BlogPosting · FAQPage · Blog · CollectionPage, publisher `SITE/#business`).

상수(파일 맨 위): `SITE='https://www.hdplan.co.kr'` · `BRAND='HD기획'` · `TEL` · `쪽당=24`. CSS 는 파일 안 `CSS` 문자열, 머리 · 꼬리 · 상담 상자는 `머리()` · `꼬리` · `상담` 템플릿.

## 5. 검사기 `blog-check.mjs`

```bash
node scripts/blog-check.mjs                    # 모든 글(중복 비교는 가장 최근 날짜 글만)
node scripts/blog-check.mjs --new a.json b.json  # 새 글만 엄격히 + 기존 글 전부와 중복 비교
```
실패하면 `✗` 목록과 exit 1, 주의는 `△`(통과는 됨).

| 사진 | photos.json 에 없음 · `제외` · 같은 묶음 2장 · 파일 없음 · alt 8~120자 아님 · caption 없음 · 사진 정보와 다른 지역 이름을 alt/caption 에 씀 · 3장 미만 | |
| 링크 | 없는 내부 주소(파일 존재 확인), `/`·`https://` 아닌 링크 | `/quote.html` 링크 없음, 내부 링크 2개 미만 |
| 견적 | 제목에 「견적」이 든 섹션의 표 첫 칸이 견적 품목 낱말(`quote-catalog.js` 의 `name:` + 운반·설치·인력 등 공통어)이 아님, 「파라솔 · 냉풍기 · 온풍기 · 난방기 · 이동식 화장실 · 케이터링 · 도시락 · 셔틀버스 · 꽃장식 · 가구 · 드론쇼 · 불꽃」을 빌려준다/준비해 드린다고 약속 | |

| 출처 | sources name/url 형식, 공식 도메인인데 sources.json 주소와 다름, 법 · 시행령 · 조례 · 기상청 · 고시 · 지침 · 데이터랩 · 소비자원을 말했는데 sources 비었음 | |
| 근거 | 3개 미만, 본문에 그대로 없음, regions.json 근거 25자 초과 · 그 지역 자료에 없음, 핵심(이동 · 주의 · 현장기록) 근거 0개, 출처가 sources 에 없는 주소. `주의` 중 `(작성자용` 으로 시작하는 줄은 근거로 못 씀 | |
| 중복 | 같은 지역 · 같은 주제 글 존재, 지역 이름을 지운 본문 4글자 조각의 자카드 겹침 > 30% | 20~30% |

## 6. 계획기 `blog-plan.mjs`

- 지역: `비중`(합 1) × (기존 글 + 이번 고른 수) 대비 모자란 지역부터.
- 주제 점수 = 검색량(없으면 0.15, 최소 0.05) × 보정 × 계절(앞으로 1~2달이 성수기 1.6, 이번 달 1.3, 아니면 1). 지역전용은 ×1.3 이고 같은 주제의 일반 틀을 대신한다.
- 같은 지역에 이미 쓴 주제는 빼고, 같은 날 같은 주제는 점수 ×0.5.
- 후보가 모자라면 「keywords.json 에 주제를 보충할 때다」를 출력.
- 2026-10-28 실행 결과: 이미 10편, 남은 후보 116개, 추천 광명 송년회 · 영등포 워크숍 · 강남 기공식 · 구로 무대LED · 관악 기관행사.
- `keywords.json` 의 `검색량` · `보정` 은 비어 있다(2026-10-13 네이버 데이터랩 미조사). 조사하면 「광명 행사대행」=1 로 둔 상대값으로 적는다.

## 7. 자료 파일 요점

- **regions.json** 9곳: 금천 0.14 · 구로 0.10 · 광명 0.12 · 관악 0.10 · 영등포 0.12 · 마포 0.10 · 강남 0.12 · 송파 0.10 · 남양주 0.10. `이동` 은 make_pages.py `AREAS` 와 같은 값. 현장기록은 영등포 「국회 개방행사 놀이존 운영(2024, 국회)」 하나. `주의` 에는 작성자용 경고(예: 「통계처럼 쓰지 않는다」)가 섞여 있다 — 글에 옮기지 않는다.
- **keywords.json** 주제 14: 송년회 · 체육대회 · 워크숍 · 업체선정 · 음향조명 · 무대LED · 기공식 · 시상식 · 학교행사 · 놀이존 · 기관행사 · MC섭외 · 우천대비 · 안전계획. 지역전용 1: 영등포 놀이존.
- **photos.json**: sys · slider · hero_poster 중심 19묶음이 사용 가능, `slider1`(얼굴) · `slider4`(단체 얼굴) · `sys/h1_1`(자료 화면) · works 19장 묶음 · biz 8장 묶음은 `제외`. 모든 사진의 `지역` 이 비어 있다 → 캡션에 지역을 쓰면 검사기에 걸린다.
- **sources.json** 7개(확인일 2026-09-11): 기상청 특보 기준(강풍주의보) · 생활법령 재해대처계획 신고 · 공연법 시행령 제9조 · 재난안전법 시행령(지역축제 안전관리계획) · 한국소비자원 에어바운스 · 정책브리핑 유원시설 규제 · 네이버 데이터랩. 새 출처는 **사람이 확인해서** 추가.

## 9. 다른 사이트로 이식하는 절차

이 체계는 「정적 사이트 + GitHub Pages + 도메인 루트」를 전제로 한다. 순서대로:

### 9-1. 복사할 것
```
scripts/build-blog.mjs  scripts/blog-check.mjs  scripts/blog-plan.mjs
_blog/GUIDE.md  _blog/regions.json  _blog/keywords.json  _blog/photos.json  _blog/sources.json
(_blog/posts/ 는 빈 폴더로 시작 — HD기획 글을 가져가지 않는다)
```
`sources.json` 은 법 · 기관 출처라 그대로 써도 되지만 「확인일」을 보고 다시 확인한다.

### 9-2. 대상 사이트에 먼저 있어야 하는 것
- 도메인 루트에서 서비스(블로그 링크 · 사진 · 파비콘이 `/blog/` `/assets/…` 같은 **루트 절대 경로**).
- `sitemap.xml`(끝이 `</urlset>`), `llms.txt` — 없으면 생성기가 그 부분을 건너뛴다.
- 대문 JSON-LD 에 `@id: "<SITE>/#business"` 인 Organization/LocalBusiness — 블로그의 `publisher` 가 이것을 가리킨다.
- 견적 품목 파일: 검사기가 `quote-catalog.js` 를 `readFileSync` 로 읽고 `name:'…'` 을 뽑는다. **없으면 검사기가 바로 죽는다.** 품목 파일 경로/형식이 다르면 `blog-check.mjs` 의 `품목이름` 줄을 고친다.
- `_blog/` 가 공개되지 않게: GitHub Pages(Jekyll)는 밑줄 폴더를 빼 준다. `.nojekyll` 을 쓰는 사이트면 `_blog/` 가 공개되니 따로 막는다.

### 9-3. `build-blog.mjs` 에서 바꿀 곳
| 자리 | HD기획 값 |
|---|---|
| `SITE` · `BRAND` · `TEL` | `https://www.hdplan.co.kr` · `HD기획` · 대표 번호 |
| `CSS` 의 `:root` 색 | `--acc:#F0472B; --acc-ink:#C9371F; --acc2:#FF7A4D; --ink:#111318; --navy:#101522 …`, 푸터 `#0B0E15` |
| `머리()` | 파비콘 경로, `theme-color`, 글꼴 링크, **stats.js `data-site`**, 상단 로고(`.mark` 「HD」) · 메뉴 링크 |
| `꼬리` | 대표 · 주소 · 전화 · 이메일 · 링크 줄 |
| `상담` | 「1영업일 … 답사는 무료」 같은 회사 약속 문구 |
| 목록 · 지역 모음 제목 · 설명 | 「서울 · 광명 · 남양주 …」 지역 문구 |
| llms.txt 절 첫 줄 · rss description | 지역 문구 |
| 사진 경로 | HD기획판은 `SITE + path`(이 저장소). 큰길이벤트 원판은 CDN 이었다 — 대상 사이트가 어느 쪽인지 맞춘다 |

### 9-4. `blog-check.mjs` 에서 바꿀 곳
- `금지` 의 경쟁사 이름 정규식(`프로이벤트|나인엠씨|NINEMC|PRO\s*EVENT`) → 그 회사가 벤치마킹한 업체 이름으로.
- `없는품목` · `약속말` → 그 회사 견적서에 없는 품목으로.
- `견적낱말` 공통어 목록 → 그 회사 업종에 맞게.
- 사진 파일 존재 확인은 `resolve(ROOT, '.' + im.path)` — 사진이 레포 밖(CDN)이면 이 줄을 바꾼다.

### 9-5. `_blog/` 자료 다시 쓰기
1. **GUIDE.md** 4장 「쓸 수 있는 회사 사실」을 그 회사 사이트에 **실제로 적힌 것만**으로 다시 쓴다. 2장의 금지 항목(경쟁사 · 워터마크 · 예시 숫자)도 그 회사 사정으로.
2. **regions.json**: 그 회사 운영 지역. `이동` 은 본사 → 관공서 거리(지도 서비스로 확인한 값, 조회일 적기), `현장기록` 은 사이트에 이름이 있는 행사만. `서비스페이지` 는 실제 있는 지역 페이지 주소(없으면 `""`). `비중` 합 1.
3. **keywords.json**: 업종 주제 틀. `검색량` 은 조사 전이면 비워 둔다.
4. **photos.json**: 그 회사 사진을 하나씩 보고 `보이는것` · `쓰임` 작성, 얼굴 · 워터마크 · 자료 화면은 `제외`. 같은 장면 여러 장은 한 묶음 `path` 배열로.
5. **sources.json**: 사람이 연 공식 출처만.

### 9-6. 사이트에 연결
- 메뉴 · 푸터에 `블로그` 링크(`/blog/` 또는 상대 `blog/`).
- `robots.txt` 는 그대로(블로그는 공개).
- 첫 글을 쓰고 `blog-check --new` → `build-blog` → 브라우저로 `/blog/` · 글 한 편 · 지역 모음 한 곳을 연다(콘솔 오류 · 깨진 사진 · 375px 가로 스크롤 확인).
- 검색 알림: IndexNow 키 파일(`<키>.txt`, 내용 = 키)을 루트에 두고 새 주소를 알린다. 네이버 서치어드바이저 · 구글 서치콘솔은 소유 확인 태그를 받은 뒤.

### 9-7. 이식 뒤 자주 생기는 문제
- 다른 생성기가 sitemap.xml 을 통째로 다시 쓰면(HD기획의 `make_pages.py` 처럼) 블로그 줄이 사라진다 → 그 생성기 뒤에 `build-blog.mjs` 를 다시 돌리거나, 그 생성기를 「/blog/ 줄은 두기」로 고친다.
- 하위 경로 배포(`user.github.io/repo/`)에서는 루트 절대 경로가 깨진다 → 도메인을 붙이거나 템플릿 경로를 바꾼다.
- 옛 llms.txt 교체 코드를 가져오면 목록이 겹친다 → 4-4 의 2026-10-28 판을 쓴다.
- 검사기의 4글자 겹침은 **지역 이름만** 지우고 비교한다. 같은 주제를 다른 지역으로 쓸 땐 목차부터 새로 짠다.
