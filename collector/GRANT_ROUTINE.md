# 공모사업 주간 갱신 루틴

매주 월요일 오전, 사람 없이 돈다. 이 루틴이 `collector/grants_curated.json` 을 고치고 `events.json` 의 공모사업(kind: grant)만 바꿔
라이브(이벤트 코리아 · 큰길이벤트 · 행사 고시 알림판)에 올린다. **사람이 보지 않고 올라가므로 지어내지 않는 것이 전부다.**

## 0. 지켜야 할 것

- **검색 요약문을 사실로 쓰지 않는다.** 검색 도구의 요약은 서로 모순되거나 다른 공고의 주소를 붙인다(2026-10-10 실제로 확인).
  사실은 **공식 공고 페이지 원문**에서만 가져온다. 원문은 `python collector/validate_grants.py --peek <주소> [키워드 …]` 로 읽는다.
- **근거 문장(`evidence`)은 `--peek` 출력에서 한 글자도 바꾸지 말고 복사한다.** 검사기(`--check-urls`)가 그 문장이 그 주소의 실제
  페이지에 있는지 대조해서, 없으면 항목을 막는다. 검사기가 막은 항목을 살리려고 글자를 비틀거나 검사기를 고치지 않는다 — 지운다.
- 제목 · 기관 · 기간 · 링크까지만 적는다. 지원내용 · 금액 · 자격 본문은 옮기지 않는다(프로젝트 규칙 「본문 전재 금지」).
- **게시판(목록) 페이지를 훑지 않는다.** 문화포털 지원사업 캘린더, 각 재단의 공지 목록은 읽지 않는다(프로젝트 규칙 「게시판 HTML 직접 파싱 금지」).
  읽는 것은 ① 검색으로 찾은 **개별 공고 페이지** ② 아르코 「문예진흥기금 공모 한눈에 보기」(내용 페이지) 뿐이다.
- 블로그 · 카페 · SNS · 뉴스 기사 주소는 근거가 아니다. 근거 주소는 기관 누리집(`.kr`)의 공고 페이지다.
- 한 번에 새 항목은 최대 10건. **0건도 정상이다.** 못 찾았다고 억지로 채우지 않는다.
- 조사량: 검색 12회 이하, `--peek` 30회 이하. (`--peek` 은 robots.txt 를 지키고 요청 간격을 둔다 — 도구가 보장한다.)
- 키 · 토큰 · 개인정보를 출력하거나 파일에 쓰지 않는다. 이 문서와 `validate_grants.py` · `grant.py` 의 규칙은 바꾸지 않는다.

## 1. 순서

1. 작업 폴더: `C:\클로드코드2`. `git pull --rebase`(작업 중인 다른 변경이 있으면 `-c rebase.autoStash=true`). 오늘 날짜(한국)는
   `python -c "from datetime import datetime,timedelta;print((datetime.utcnow()+timedelta(hours=9)).date())"`.
2. **기존 항목 점검**
   - `python collector/validate_grants.py --prune` (마감이 14일 넘게 지난 항목을 지운다)
   - `python collector/validate_grants.py --check-urls`
   - 실패한 항목마다 `--peek` 로 그 주소를 다시 읽는다. 날짜가 바뀌었으면(공모 기간 연장 등) 페이지 글자 그대로 `deadline`·`end_date`·`evidence`·`checked_at` 을 고치고,
     페이지가 없어졌거나(404) 읽을 수 없으면(스크립트로만 그려지는 페이지, robots 거부) 그 항목을 지운다.
3. **아르코 일정표** — `--peek https://arko.or.kr/content/6220 별도공모 마감` 으로 읽는다. 새로 일정이 정해진 사업(별도 공모 등)이나 바뀐 기간이 있으면 반영한다.
4. **새 공모 찾기** — 아래 「검색어」로 WebSearch. 결과에서 **기관 누리집의 개별 공고 주소**(.kr)만 후보로 삼아 `--peek` 로 원문을 읽고 다음을 모두 확인한다.
   - 주관 기관 이름과 공고 제목이 원문에 있다.
   - 접수 마감일이 **오늘 이후 120일 안**이고 원문에 적혀 있다. (시작 전이면 접수 예정으로, 제목에 「예정」을 넣고 시작일을 `start_date` 에)
   - 대상이 **법인·단체·업체·예술인**이고 분야가 문화예술·공연·축제·행사다. 제외: 개인 장학금 · 수강생 · 동호회 · 자원봉사 · 채용 · 공간 대관 모집 · 단순 참가자 모집 · 이미 마감.
   - 이미 목록에 있는 공고(같은 기관·같은 사업)는 건너뛴다.
5. **항목 쓰기** — `grants_curated.json` 의 `items` 에 추가:
   ```json
   {
     "id": "기관영문약칭-yyyymm-짧은이름",          // 영소문자·숫자·- 만, 유일
     "title": "공고 제목 그대로",                    // 8~120자
     "org": "주관 기관 이름",
     "source": "기관 이름(짧게)",
     "posted_at": "YYYY-MM-DD", "start_date": "YYYY-MM-DD", "end_date": "YYYY-MM-DD",
     "deadline": "YYYY-MM-DD HH:MM",                // 시각이 원문에 없으면 날짜만
     "summary": "사업 이름 목록 정도(200자 이하, 지원내용·금액 금지)",
     "url": "https://… 개별 공고 주소",
     "evidence": "--peek 출력에서 복사한 근거 문장(날짜 포함, 12~240자). 두 곳에 떨어져 있으면 「앞 조각 … 뒤 조각」",
     "checked_at": "오늘 날짜"
   }
   ```
6. **검증** — `python collector/validate_grants.py --check-urls` 가 `모두 통과` 할 때까지. 실패 항목은 고치지 말고(원문과 다른 글자를 만들지 말고) 지운다.
7. **시험** — `python collector/tests.py` 가 OK 여야 한다.
8. **반영** — `python collector/run.py --refresh grant` (events.json 의 공모사업만 바뀐다. 나라장터·축제는 그대로).
9. **올리기** — `git add collector/grants_curated.json site/data/events.json` → 커밋 메시지 `공모사업 주간 갱신 YYYY-MM-DD — 추가 N · 수정 M · 삭제 K` + 끝에
   `Co-Authored-By: Claude …` → `git push`. 거절되면 `git pull --rebase` 후 8번부터 다시.
10. **보고** (한국어, 짧게)
    ```
    공모사업 주간 갱신 YYYY-MM-DD
    추가 N: 기관 · 제목 · 마감
    수정 M: …   삭제 K: …(이유)
    확인했지만 못 올린 것: 제목 — 이유(검증 실패 · 개인 대상 · 이미 마감 …)
    확인이 필요한 점: (없으면 「없음」)
    ```

## 2. 검색어 (돌려 가며 쓴다)

- `{재단명} {내년} 지원사업 공모 접수` — 재단명은 매주 4~5곳씩 돌린다: 서울 · 경기 · 부산 · 대구 · 인천 · 광주 · 대전 · 울산 · 세종 · 강원 · 충북 · 충남 · 전북 · 전남 · 경북 · 경남 · 제주 문화재단(또는 문화예술진흥원 · 문화관광재단)
- `지역문화행사 지원 운영단체 공모 {재단명}`
- `공연예술 지원사업 공모 접수 {내년} 문화재단 단체`
- `지역축제 지원 공모 문화관광재단 접수`
- `예술인 지원 공모 {내년} 접수 시작 {이번 달}`
- 아르코(한국문화예술위원회) · 한국콘텐츠진흥원 · 한국관광공사 · 문화체육관광부 공고도 같은 방식으로.

## 3. 실패했을 때

- `git push` 가 계속 거절되면 멈추고, 어디서 막혔는지만 보고한다(강제로 밀지 않는다).
- 검증기가 전부 실패하면(네트워크 문제 등) 파일을 건드리지 말고 그대로 두고 보고한다.
- 다른 곳(이벤트 코리아 · 큰길이벤트 저장소)은 건드리지 않는다. 화면은 알아서 `events.json` 을 읽는다.
