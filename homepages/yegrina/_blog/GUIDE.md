# 한국체대 예그리나 블로그 작업 설명서

예그리나 홈페이지(brizymedia.github.io/yegrina/)의 **행사 준비 블로그**(`blog/`)에 지역별 정보 글을 올릴 때 따르는 규칙이다. HD기획 `_blog/GUIDE.md` 를 예그리나에 맞게 옮겼다. 사람이 고칠 때도 이 문서를 먼저 고친다.

- 읽는 사람: 어린이 행사를 맡은 사람 — 어린이집 · 유치원 원장님과 선생님, 초등학교 체육 · 행사 담당 선생님, 교회 교육부 · 행사 담당자, 아파트 커뮤니티 · 문화센터 담당자.
- 목표: 네이버 웹문서 · 구글 · AI 검색(SEO · GEO · AEO)에서 "지역 + 운동회 · 체육대회 · 발표회 · 물놀이 · 놀이기구" 검색에 걸리는 것. 광고 글이 아니라 **담당자가 저장해 두고 싶은 체크리스트**여야 한다.
- 원칙: 틀린 정보 한 줄이 글 한 편보다 해롭다. **확인 못 한 것은 쓰지 않는다.** 그럴듯하게 지어낸 지역 이야기와 회사 약속이 가장 위험하다.

---

## 1. 순서

1. `node scripts/blog-plan.mjs` 로 다음에 쓸 글(지역 · 주제 · 키워드)을 받는다.
2. 글마다:
   1. `_blog/regions.json` 에서 그 지역의 `이동 · 동네 · 주의 · 현장기록` 을 읽는다. **지역 이야기는 여기 있는 것과 출처를 단 사실만 쓴다.** 지금 `현장기록` 은 전부 비어 있다(블로그 원문에 장소가 적혀 있지 않다) — "○○에서 한 운동회" 같은 실적을 쓰지 않는다.
   2. 같은 주제로 다른 지역에 쓴 글이 있으면 읽되 **베끼지 않는다**. 목차부터 새로 짠다.
   3. 법 · 기준 · 기관 이야기는 `_blog/sources.json` 에 있는 출처와 그 `사실` 범위 안에서만 쓴다. 그 기관 도메인의 다른 주소는 검사기가 막는다. 필요한 기준이 없으면 그 내용은 쓰지 않는다.
   4. 사진 3~4장을 `_blog/photos.json` 에서 고른다(5장).
   5. `_blog/posts/<날짜>-<slug>.json` 을 쓴다(3장). **`근거` 칸을 반드시 채운다.**
   6. `node scripts/blog-check.mjs --new <파일>` 이 통과할 때까지 고친다. 검사기를 통과시키려고 동네 이름이나 자료 문장을 억지로 끼워 넣지 않는다 — 그럴 거면 그 글을 버린다.
3. `node scripts/build-blog.mjs` 로 `blog/` 를 다시 만든다(sitemap.xml · llms.txt · rss.xml 도 같이 갱신된다). 결과 HTML 은 손으로 고치지 않는다.
   - `python tools/make_pages.py` 는 sitemap.xml 을 새로 쓰면서 블로그 주소를 지운다. 그걸 돌렸으면 **반드시 build-blog 를 다시 돌린다.**
   - 블로그 머리글 · 메뉴 · 바닥글은 `notice.html` 에서 빌려 온다. 메뉴를 바꾸려면 notice.html(과 다른 기본 페이지)을 고치고 make_pages · build-blog 를 다시 돌린다.
4. 커밋 · 푸시. GitHub Pages 가 1분 안에 반영한다. 검색 등록(네이버 서치어드바이저 · IndexNow)은 전용 도메인을 연결한 뒤에 한다.

## 2. 절대 쓰지 않는 것

검사기(`scripts/blog-check.mjs`)가 일부를 막지만 전부는 못 막는다.

**① 회사가 하겠다고 한 적 없는 약속 · 서비스**
- 회사가 할 수 있다고 말하는 것은 4장 목록뿐이다. 그 밖의 것(음향 장비 · 조명 · 무대 설치 · LED · 현수막 · 테이블 · 트로피 · 상품 · 간식 · 사진 촬영 · 보험 · 셔틀버스 등)은 빌려준다거나 해 준다고 쓰지 않는다. "원 · 학교 · 교회가 확인할 일"로 쓴다.
- regions.json `주의` 칸의 작성자용 메모를 글에 옮기지 않는다.

**② 회사 경험을 늘려 말하기**
- "수많은 행사를 맡아 왔습니다" 같은 말을 쓰지 않는다. 경험은 [행사 이야기](/stories/index.html) 다섯 편에 적힌 **행사 이름**으로만 말한다(교회 전교인 체육대회 · 초등학교 운동회 · 어린이집 · 유치원 체육대회 · 여름성경학교 물놀이 · 비 예보로 실내놀이터로 바꾼 여름성경학교). 이 행사들에는 장소가 적혀 있지 않으니 **어느 지역에서 했다고 쓰지 않는다.**
- 연혁(2014년 설립 등) · 경력 연수(20년) · 「매년 50개원 이상」 같은 숫자 · 자격 개수는 대문에 있어도 대표 확인 전이라 블로그에서 쓰지 않는다.

**③ 근거 없는 지역 이야기**
- 동네 이름에 특징을 붙이기("다산신도시처럼 아이가 많은 곳") — 동네 이름은 "(별내 · 다산 · 진접 등)"처럼 **괄호 속 나열로만** 쓴다.
- 문의 통계 지어내기("노원은 실내놀이터 문의가 많습니다"), 지역 성격 지어내기, 다른 지역과 견주기.
- 대신 "흙 운동장은 바람 부는 날 먼지가 일기 쉽습니다"처럼 **지역 이름을 붙이지 않은 일반 요령**으로 쓴다.

**④ 그 밖에**
- 가격 · 단가 · "○○원" — 하는 일 페이지에 참고 비용이 있어도 블로그에는 쓰지 않는다(상담 후 안내).
- 후기 · 고객 발언 · 만족도 · 순위 · 행사 건수 · 참가 인원 수.
- 사진: 아이 얼굴이 나온 사진(모자이크가 있어도 앞모습 · 가까운 사진은 쓰지 않는다), 선생님 얼굴이 크게 나온 사진, 목록에 없는 사진, AI 그림. 지역을 모르는 사진은 캡션에 지역을 쓰지 않는다(지금은 전부 모른다).
- 다른 업체 비방, 경쟁사 이름. "무조건 · 100% · 보장 · 최고의".
- 아이 안전에 관한 의학 · 법률 조언을 단정하지 않는다. 출처가 있는 것만, 없으면 "원 · 학교의 안전 기준을 따른다"로 쓴다.

## 3. 글 형식 (JSON)

| 칸 | 규칙 |
|---|---|
| `slug` | 한글 · 영소문자 · 숫자와 `-`, 70자 이하. 지역 이름 + 핵심 키워드 + 약속 |
| `date` | `YYYY-MM-DD`. 파일 이름은 `<date>-<slug>.json` |
| `region` | `_blog/regions.json` 의 slug (`namyangju`, `uijeongbu` …) 또는 `common` |
| `topic` | `_blog/keywords.json` 의 topic. 같은 지역에 같은 topic 은 한 번만 |
| `title` | 15~50자. 지역 이름을 앞쪽에, 핵심 키워드를 통째로 |
| `description` | 70~160자. 누구에게 무엇을 정리했는지. 핵심 키워드 포함 |
| `keyword` | `{ "main": 핵심 키워드, "sub": [보조 키워드들] }` |
| `lead` | 80~420자. 첫 문장에 핵심 키워드와 결론 |
| `points` | 3~5개. 본문을 안 읽어도 답이 되는 문장 (AI 검색이 그대로 인용하는 자리) |
| `cover` | `{ "path", "alt", "caption" }` |
| `sections` | 4~8개. `{ "h2": "1. …", "blocks": [ … ] }` — h2 하나 이상에 지역 이름이나 키워드 |
| `faq` | 2~6개. `{ "q", "a" }` — 실제로 받을 법한 질문. 답에서 새 약속을 만들지 않는다 |
| `근거` | **3개 이상.** `{ "내용": 본문에 그대로 있는 구절, "출처": "regions.json" 또는 이 글 sources 의 주소 }`. regions.json 근거는 25자 이하 핵심어로, 그중 하나 이상은 `이동 · 주의 · 현장기록`에서 |
| `sources` | `{ "name", "url" }` — 법 · 기준 · 기관을 말했으면 반드시. 공식 기관은 sources.json 주소 그대로 |

`blocks`: `{ "p" }` · `{ "ul": [] }` · `{ "ol": [] }` · `{ "table": { "head": [], "rows": [[]] } }` · `{ "img": { "path", "alt", "caption" } }` · `{ "tip": 현장 메모 }`
꾸밈은 `**굵게**` 와 `[글자](/주소 또는 https://…)` 뿐. 내부 주소는 **사이트 루트 기준**(`/quote.html`, `/areas/uijeongbu.html`, `/blog/<slug>/`)으로 쓴다 — 사이트가 `/yegrina/` 아래에 있어도 build-blog 가 상대 주소로 바꿔 준다.

## 5. 사진

- `_blog/photos.json` 에 있고 `제외`가 없는 사진만. 표지 1장 + 본문 2~3장. **같은 `묶음`(같은 행사)에서 두 장을 쓰지 않는다.**
- `alt` — 사진에 보이는 것(8~120자). `caption` — "장면 — 무엇을 보여 주는지". 목록의 `지역`이 비어 있으면 캡션에 지역을 쓰지 않는다(지금은 전부 비어 있다).
- 표지는 되도록 기존 글과 겹치지 않게.

## 6. 좋은 글의 기준

- 합니다체, 짧은 문장, 쉬운 말. 첫 문단이 답이다.
- 지역 사실 3가지 이상, 전부 근거가 있어야 한다(regions.json 의 이동 · 주의가 가장 좋다. 동네는 이름 나열로만).
- 표 1개 이상(체크리스트 · 준비표 · 견적 항목표). 내부 링크 2개 이상: `/quote.html` 반드시, 지역 페이지(`/areas/<slug>.html`), 관련 글(`/blog/<slug>/`).
- 핵심 키워드는 제목 · 설명 · 첫 문단 · 소제목 하나에 자연스럽게(본문 12번 넘으면 경고).
- 본문 1800자 이상(2500자 권장). 같은 주제를 다른 지역에 쓸 때 본문이 30% 넘게 겹치면 막힌다.
